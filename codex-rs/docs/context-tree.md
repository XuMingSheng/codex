## Summarizing the tree

`codex-context-tree` keeps a nested hierarchy of labels and entries, but the actual text summarization happens inside the core’s `ContextTreeSummarizer`. When a session has a context-model configured (`SessionConfiguration::context_model` + provider/family), `ContextManager` creates a session-scoped `ModelClient` and hands it to the tree via `ContextTreePromptModel`. The summarizer feeds concatenated child summaries into that client using `ContextTreePromptModel::complete`, which builds a `Prompt` with the configured system instructions and a single user message holding the combined text, then streams through the `ModelClient` until it receives the final assistant message (captured from `ResponseEvent::OutputItemDone`).

If no context model is configured or the streaming call fails, the summarizer simply keeps the raw concatenated text, so summaries always exist even without the model path. This keeps the crate protocol-agnostic—core is responsible for translating `ResponseItem`s into entry payloads/labels, calling `commit_history_mutation`, and later converting the cached tree back into `PromptContextTree` snapshots, while the tree owns the incremental caches, node states, and optional summarization helper.
